# DX cluster and reverse-beacon servers
#
# The servers offered in Settings -> DX Cluster / RBN. These are other
# people's machines, run by volunteers at their own expense, so treat this
# list as a guest list rather than an API: connect to one at a time, and do
# not add a server you have no reason to be on.
#
# Before connecting, know what leaves this machine. A cluster login requires
# a callsign, sent unencrypted, and CW Buddy sends yours in answer to the
# server's prompt followed by the setup commands below. It sends nothing else
# -- no spots, no announcements, no replies. Your callsign reaching the server
# operator, and usually the other logged-in users, is the cost of joining.
#
# One server per line:
#
#   name | host | port | source | login commands | note
#
# source          rbn for a reverse-beacon feed -- a receiver reporting what
#                 it decoded -- or cluster for human-entered spots. They are
#                 weighed differently and agreement between them counts for
#                 more than either alone, so do not relabel one as the other.
# login commands  separated by ';', sent after login, may be empty. The token
#                 {BAND} is replaced with the band the receiver is on, as an
#                 ADIF band name such as 20m. A command containing it is sent
#                 again whenever the radio changes band, so the server's own
#                 filter follows the receiver; one without it is setup and is
#                 sent once. A command is skipped entirely while the band is
#                 unknown, because a filter with a hole in it is a syntax
#                 error on somebody else's server.
#
#                 {BANDNUM} is the same band as a bare number -- 20, not 20m
#                 -- because the two networks disagree about the name and one
#                 refuses the other's form.
#
#                 The syntax differs by cluster software and every command
#                 here was watched being accepted by a live server rather than
#                 taken from documentation:
#
#                   DXSpider     accept/spots 0 on {BAND}/cw
#                                GB7DJK echoed it back through sh/filter as
#                                `filter0 accept on 20m/cw`.
#
#                   AR-Cluster   set/dx filter band={BANDNUM} and mode=cw
#                                NC7J rejected `band=20m and mode=cw` with
#                                "did not pass validation" and accepted
#                                `band=20 and mode=cw`, reporting it back as
#                                `Filter: band = 20 and mode = cw`. The suffix
#                                is the whole difference.
#
#                 CC Cluster nodes carry no band command. Its login banner
#                 lists its whole command set and there is no band filter in
#                 it, and nothing was seen to be accepted, so it is filtered
#                 on arrival like every server is anyway. Add a command for a
#                 server only after watching that server accept it: a guess
#                 earns an error reply and a filter that quietly is not there,
#                 submitted under the operator's callsign.
# note            shown beside the entry in Settings.
#
# Blank lines and lines starting with '#' are ignored. A line that does not
# parse is skipped, so one bad edit cannot leave you with no servers at all.
#
# Edit freely: this file is read at startup and never compiled in.

# --- Reverse beacon: receivers, not people ---
#
# The RBN is a network of skimmers decoding CW continuously and reporting
# every call they hear with a measured signal-to-noise ratio and speed. It is
# the most useful source here for a CW decoder, and the only one that is
# itself a receiver. Port 7000 carries CW and RTTY; port 7001 carries FT8 and
# is deliberately not offered, because nothing in CW Buddy can use it.
# No login commands: the RBN telnet port accepts none. Its feed arrives
# unfiltered at roughly six spots a second worldwide and is filtered on
# arrival instead, against the band being received.
Reverse Beacon Network (CW/RTTY)|telnet.reversebeacon.net|7000|rbn||Skimmers worldwide, reporting CW with signal-to-noise and speed. The best match for CW decoding.

# --- Cluster: people, and the skimmers their servers relay ---
#
# Spot rates vary enormously between these. A server relaying skimmer output
# can send several spots a second; one carrying only human spots sends a few
# a minute. Both are useful, for different reasons.
VE7CC (CC Cluster, Vancouver)|dxc.ve7cc.net|23|cluster|SET/SKIMMER;SET/NOFT8;SET/NOFT4;SET/NOBEACON|Well-run CC Cluster node. Skimmer spots enabled, FT8 and FT4 suppressed.
NC7J (AR-Cluster, Utah)|dxc.nc7j.com|7373|cluster|SET/SKIMMER;SET/NOFT8;set/dx filter band={BANDNUM} and mode=cw|AR-Cluster v6 with an attached CW and RTTY skimmer server.
DXFun (Spain)|dxfun.com|8000|cluster||Long-running European node with a large user base.
W3LPL (Maryland)|dxc.w3lpl.net|7373|cluster|SET/SKIMMER;SET/NOFT8;set/dx filter band={BANDNUM} and mode=cw|North American node fed by the W3LPL skimmer array.
GB7DJK (DXSpider, UK)|gb7djk.dxcluster.net|7300|cluster|accept/spots 0 on {BAND}/cw|DXSpider node run by the author of DXSpider; answers as GB7TLH.
